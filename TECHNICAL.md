# Technical notes

Documentation of how this repository is put together — for maintaining the
decks, not for students (see [README.md](README.md) for the student-facing
landing page).

## Architecture

The decks are [reveal.js](https://revealjs.com) presentations with three kinds
of interactive content:

- canvas-based magnetization widgets written in vanilla JS (no external
  dependencies) in each deck's `js/widgets.js`
- Plotly figures (interactive D-6A core logs) generated by a per-deck build
  script from data in the sibling `2026_SSRM_Duluth_Complex` repository
- a folium/Leaflet location map copied from `2026_SSRM_Duluth_Complex`

`index.html` at the repository root is the landing page served by GitHub
Pages; it links to each deck's `index.html`.

## Per-deck vendoring

Each deck folder is fully self-contained: reveal.js, KaTeX, and Plotly.js are
vendored in the deck's `lib/` directory rather than shared at the repository
root or loaded from CDNs. This is deliberate:

- a downloaded deck folder works offline when `index.html` is opened directly
- Safari restricts `file://` pages to subresources within their own directory
  and below, so assets referenced via `../` render in Chrome but silently fail
  in Safari — per-deck `lib/` keeps every deck double-clickable in Safari

When creating a new deck (S2, S3), copy the `lib/` folder from
`S1_Duluth_dia_para_ferro/` into the new deck directory. Details of what is
vendored (versions, trimming) are in the
[S1 deck README](S1_Duluth_dia_para_ferro/README.md).

The one exception to offline operation is the Leaflet location map, whose
libraries load from CDNs and whose basemap tiles stream from OSM/Esri.

## Local development

Serve the repository root and browse to the landing page:

```
python -m http.server
# then http://localhost:8000/
```

Opening a deck's `index.html` directly via `file://` also works (see the
Safari note above). Press `s` in a deck for speaker notes.

## Regenerating interactive figures

Each deck's README documents how to regenerate its interactive figures — for
S1, `build_D_6A_interactive.py` (run in the `ess-jbook` environment) rebuilds
the Plotly core logs from CSVs in the sibling `2026_SSRM_Duluth_Complex`
checkout; for S2, `build_anisotropy_interactive.py` (same environment)
rebuilds the three 3-D anisotropy-energy-surface figures adapted from the
Essentials JupyterBook chapter 4 code cells, and
`images/build_para_figures.py` rebuilds the Langevin-function and
Curie-law figures; for S3,
`build_FC_zijderveld.py` (same environment; also needs the PmagPy checkout
importable) rebuilds the demagnetization figure from the MagIC tables in the
sibling `2020_Duluth_Complex` checkout. S2 embeds the chapter 5
flipping-field widget and S3 the three chapter 7 Néel-diagram widgets from
the Essentials JupyterBook, localized for offline use as described in the
[S2](S2_fine_particle_magnetization/README.md) and
[S3](S3_remanent_magnetization/README.md) deck READMEs.
